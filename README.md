# ΟΑΧ: ειδοποιήσεις Telegram με GitHub Actions

Το κινητό δεν χρειάζεται να παραμένει ανοιχτό. Το GitHub εκτελεί το πρόγραμμα περίπου κάθε 30 λεπτά. Τα προγραμματισμένα Actions μπορεί να καθυστερήσουν ή να μη γίνουν, και ισχύουν τα όρια/χρεώσεις του λογαριασμού GitHub. Δεν είναι υπηρεσία εγγυημένης άμεσης ειδοποίησης.

Το πρόγραμμα συνδέεται με Playwright/Chromium, διαβάζει μόνο το ημερολόγιο και στέλνει ειδοποιήσεις στο Telegram. Ελέγχει όλες τις ημέρες στο επιλεγμένο χρονικό παράθυρο, αρχικά σήμερα και τις επόμενες 6 ημέρες, για 20:00, 21:00 και 22:00. Το `days_ahead` στο `config.json` αλλάζει το παράθυρο. Δεν κάνει κρατήσεις.

## Ρύθμιση από κινητό

1. Δημιούργησε **ιδιωτικό** repository στο GitHub. Ανέβασε τα περιεχόμενα του φακέλου, διατηρώντας τη διαδρομή `.github/workflows/check.yml`. Αν το mobile upload δεν ανεβάζει κρυφούς φακέλους, δημιούργησε αυτό το αρχείο με **Add file → Create new file** και επικόλλησε το περιεχόμενό του. Το αρχείο πρέπει να είναι στο default branch.
2. Στο Telegram άνοιξε τον επίσημο **@BotFather**, στείλε `/newbot` και ακολούθησε τις οδηγίες. Αποθήκευσε το token μόνο στα GitHub Secrets. Άνοιξε το δικό σου bot και πάτησε Start / στείλε ένα μήνυμα.
3. Βρες το αριθμητικό chat ID σου από το `getUpdates` του Telegram Bot API για το δικό σου bot. Μην κοινοποιήσεις τη διεύθυνση που περιέχει το token. Για βοήθεια μπορεί να γίνει ξεχωριστή ασφαλής ρύθμιση.
4. Στο repository: **Settings → Secrets and variables → Actions → New repository secret**. Πρόσθεσε `OAX_USERNAME`, `OAX_PASSWORD`, `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`. Μην βάλεις κωδικούς σε αρχεία ή σε αυτή τη συνομιλία.
5. Στο **Actions → OAX alerts → Run workflow** επίλεξε διαγνωστικό έλεγχο. Χρειάζονται μόνο τα δύο OAX Secrets. Κατέβασε το artifact `calendar-diagnostics`. Περιέχει μόνο ώρες, γήπεδα και χαρακτηριστικά κελιών, χωρίς ονόματα μελών ή cookies.
6. **Πριν ενεργοποιήσεις ειδοποιήσεις**, επαλήθευσε σε συνδεδεμένο ημερολόγιο τον κανόνα ελεύθερης θέσης. Το στιγμιότυπο δεν αρκεί για να αποδείξει τη δομή HTML ή τη δυνατότητα κράτησης. Ο αρχικός κανόνας αναγνωρίζει αποκλειστικά το κείμενο «Νέα Κράτηση» μετά την ώρα. Αν οι διαθέσιμες θέσεις είναι κενές μετά την ώρα, ο κανόνας μπορεί να γίνει `^$`, μόνο αφού επιβεβαιωθεί ότι αυτό δεν περιλαμβάνει κλειστές/μη διαθέσιμες θέσεις. Ενδέχεται να χρειαστεί αλλαγή του parser.
7. Μετά την επιβεβαίωση βάλε `availability_verified: true` στο `config.json` και εκτέλεσε το workflow με diagnose απενεργοποιημένο. Τότε αρχίζουν και οι προγραμματισμένες ειδοποιήσεις.

## Κατάσταση και σφάλματα

Η αναγνώριση δεν έχει δοκιμαστεί σε συνδεδεμένο λογαριασμό. Μέχρι να επαληθευτεί ο κανόνας, οι προγραμματισμένες εκτελέσεις αποτυγχάνουν με σχετικό μήνυμα και δεν στέλνουν ειδοποιήσεις διαθεσιμότητας. Η λανθασμένη σύνδεση ή η μη αναγνωρίσιμη δομή είναι σφάλμα, όχι «κανένα διαθέσιμο».

Το `state.json` αποθηκεύεται στο repository για να αποφεύγονται επαναλαμβανόμενες ειδοποιήσεις. Μια θέση που εξαφανίζεται σε έναν έλεγχο και επανεμφανίζεται σε επόμενο ειδοποιείται ξανά. Αν η θέση κλείσει και ξανανοίξει μεταξύ ελέγχων, αυτό δεν ανιχνεύεται. Αποτυχία αποθήκευσης κατάστασης μπορεί να προκαλέσει διπλή ειδοποίηση. Προστασία branch που απαγορεύει push από Actions χρειάζεται προσαρμογή. Δεν αποθηκεύονται συνεδρίες ή κωδικοί στο repository.

Αν ζητείται CAPTCHA ή δεύτερος παράγοντας σύνδεσης, απαιτείται διαφορετική ρύθμιση. Δεν επιχειρείται παράκαμψη.
